Spec-driven development

OpenSpec задаёт «что», GigaFlex автономно ведёт «как»

Runner принимает change-директорию целиком. Задачи исполняются по очереди, а контекст спецификации защищён от случайного переписывания агентом.

  • `proposal.md`, `design.md` и delta specs — read-only контекст.
  • `tasks.md` — единственный изменяемый checklist выполнения.
  • Каждая группа `## N. ...` — отдельная итерация и коммит.
  • Архивация остаётся явным решением владельца change.

Автономность с проверяемыми границами

Runner сам двигает change вперёд — по одной завершённой задаче

Автономность здесь означает не «длинный prompt без контроля», а повторяемый цикл с формальными условиями завершения и безопасным возобновлением.

1

Выбрать scope

Первую незавершённую группу из `tasks.md`; поздние задачи заблокированы.

2

Выполнить

GigaCode меняет deliverable и запускает релевантные проверки.

3

Зафиксировать

Checklist/marker, чистое дерево и атомарный Git-коммит.

4

Восстановиться

Corrective retry, timeouts, rate limits и fallback на default-модель.

5

Продолжить

Следующая группа или review → finalize → явная OpenSpec archive.

Модель настраивается отдельно для каждого этапа: plan_model · task_model · review_model · finalize_model

Автономность завершается quality gate

Ревью изолировано, сравнение стабильно, решения структурированы

Пять специалистов читают один снимок результата независимо. Synthesis исправляет только подтверждённые findings и отчитывается по каждому идентификатору.

  • Immutable baseline хранит точный commit до execution branch.
  • Каждый reviewer получает disposable detached worktree.
  • Synthesis проверяет каждое замечание и исправляет только подтверждённое.
  • Чистое ревью не создаёт лишний этап; неоднозначный ответ не принимается.

Один change · одна команда

OpenSpec становится входом в автономный, но проверяемый delivery

Команда задаёт контракт. GigaFlex ведёт задачи, Git, retries, review и finalize. Архивация change остаётся осознанным финальным шагом.

  • Для разработчика — меньше ручной координации.
  • Для команды — единый SDD-процесс и воспроизводимый след.
  • Все подготовленные командами skills, rules, tools и настройки GigaCode продолжают работать в каждой сессии.
