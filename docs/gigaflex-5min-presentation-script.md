# GigaFlex: SDD через OpenSpec и автономное исполнение

Текст выступления к [пятиминутной презентации](gigaflex-5min-presentation.html).

Рассчитан примерно на пять минут при спокойном темпе речи и коротких паузах между слайдами.

## Слайд 1. SDD + автономность

**Тайминг: 0:00–0:35**

Главная проблема автономных агентов уже не в том, умеют ли они писать код. Проблема в том, как дать им работать самостоятельно и при этом не потерять управляемость.

GigaFlex решает это через SDD: OpenSpec задаёт контракт — что именно должно быть сделано, — а GigaFlex организует исполнение. Он выбирает ограниченный scope, запускает GigaCode, проверяет результат, фиксирует его в Git и передаёт на независимое ревью.

То есть автономность здесь строится вокруг спецификации, а не вокруг бесконечного промпта.

## Слайд 2. OpenSpec как контракт

**Тайминг: 0:35–1:20**

Входом для запуска становится обычный OpenSpec change.

Proposal, design и delta specs описывают требования и остаются защищённым контекстом: агент может их читать, но не должен переписывать под уже получившуюся реализацию. Изменяется только `tasks.md`, который показывает фактический прогресс.

Каждая группа задач становится отдельной границей исполнения. Runner берёт первую незавершённую группу, выполняет только её, проверяет результат и создаёт отдельный коммит. Следующие группы до этого момента остаются закрытыми.

А архивация change выполняется явно — когда команда действительно готова признать работу завершённой.

## Слайд 3. Автономный цикл

**Тайминг: 1:20–2:20**

Сам автономный цикл состоит из пяти шагов. Runner выбирает первую незавершённую группу, передаёт GigaCode спецификацию, текущий scope и командные инструкции, а затем проверяет не текст ответа, а реальное состояние проекта: файлы, тесты, checklist и Git.

Если задача не завершена, запускается корректирующая попытка. Уже сделанные изменения кода сохраняются, поэтому следующая сессия продолжает с того же места. Таймауты, ограничения API и недоступность выбранной модели также не останавливают весь запуск.

При этом для planning, выполнения задач, review и finalize можно отдельно настроить модели через `plan_model`, `task_model`, `review_model` и `finalize_model`. Это позволяет выбирать подходящий баланс скорости, стоимости и качества для каждого этапа. Если указанная модель недоступна, runner автоматически возвращается к default-модели.

После успешной проверки создаётся атомарный коммит и открывается следующий scope. То есть автономность здесь — это способность продолжать работу, восстанавливаться и выбирать подходящие ресурсы, но всегда внутри проверяемых границ.

## Слайд 4. Наблюдаемая автономность

**Тайминг: 2:20–3:05**

При этом автономный запуск не превращается в чёрный ящик.

Live dashboard показывает, на какой фазе находится процесс: выполнение задач, ревью или финализация. Видно текущую задачу, активную сессию, количество попыток, ошибки, используемые модели, время и доступную статистику по токенам.

Рядом сохраняются полный transcript и структурированная JSON-статистика. Поэтому разработчику не нужно разбирать огромный лог, чтобы понять, что сейчас происходит и где остановился процесс.

Это особенно важно для длинных запусков: автономность остаётся наблюдаемой и воспроизводимой.

## Слайд 5. Доверенное ревью

**Тайминг: 3:05–4:10**

После выполнения начинается независимое ревью.

Сначала GigaFlex фиксирует точный baseline — commit, относительно которого будет проверяться результат. Затем пять специализированных reviewer-агентов получают один и тот же снимок проекта, но работают в отдельных временных worktree.

`quality` ищет ошибки, регрессии и проблемы безопасности. `implementation` проверяет, действительно ли выполнены требования. `testing` оценивает тесты и пробелы в проверках. `simplification` ищет лишнюю сложность. `documentation` проверяет документацию и пользовательские изменения.

Reviewer-агенты только формируют замечания и не меняют проект. Затем synthesis сверяет каждое замечание с репозиторием и исправляет только подтверждённые проблемы. Если замечаний нет, лишний этап не запускается. Если ответ неоднозначен, он не принимается как корректный результат.

Таким образом, автономное исполнение заканчивается полноценным quality gate.

## Слайд 6. Запуск

**Тайминг: 4:10–5:00**

Для запуска достаточно указать GigaFlex директорию с OpenSpec change. Дальше runner самостоятельно ведёт задачи, коммиты, повторные попытки, ревью и финальную проверку.

При этом командам не нужно отказываться от уже настроенного процесса. Все skills, rules, tools и настройки GigaCode, которые команды подготовили для своих проектов, продолжают работать в каждой сессии. GigaFlex не заменяет накопленные инструкции — он использует их внутри более длинного автономного цикла.

В результате разработчик тратит меньше времени на ручную координацию, а команда получает единый SDD-процесс и воспроизводимый Git-след.

Код, инструкции и готовый сценарий запуска доступны по QR-коду.
